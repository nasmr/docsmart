# Templates

First-pass templates for the three documents in the first build slice (decision 0004), written for a BVI segregated portfolio company. **Drafts for review by BVI counsel. Not legal advice and not for use until approved by a named lawyer.**

## Markup conventions

These are the conventions the template importer (build plan B3) will parse.

| Markup | Meaning |
|---|---|
| `{{umbrella.legal_name}}` | A field filled by code from the umbrella, portfolio, asset, investor or allocation record. Never typed by hand. |
| `[[IF condition]] … [[ELSE]] … [[END IF]]` | Included only when the condition holds. |
| `[[FOR EACH item IN list]] … [[END FOR EACH]]` | Repeated for each item. |
| Blue box, `AI-DRAFTED ZONE · id` | A section the AI may draft from the sponsor's uploaded facts, with its instructions. |
| Dark box, `LOCKED · CONTRACTING PARTY` | The generated contracting-party wording. Read-only. |
| Amber box, `COUNSEL NOTE` | A question or note for counsel. Removed when a document is assembled. |

Headings use Word's Heading 1 style, and numbered headings and clauses use Word automatic numbering, as a firm's master would. Where a condition offers alternative clauses, Word numbers both (for example 3.1 and 3.2); assembly renumbers after evaluating the conditions.

Field names are listed with their sources in the guide. `fields/catalogue.json` gives each one a type, a source entity and an origin, and is the starting point for the slot schema in the data model (build plan B2 and B3). See `fields/README.md`.

## generator/

The templates are generated by a script, so wording changes stay reviewable as code diffs.

```
cd templates/generator
npm install
npm run build       # writes out/*.docx and out/_slots.json
npm run fields      # checks the templates against fields/catalogue.json, rewrites fields/usage.md
```

`lib.js` holds the rendering helpers and markup conventions. `resolutions.js`, `supplements.js` and `subscriptions.js` hold the document text. `fields.js` checks the templates against the field catalogue. `guide.js` builds the guide and fails if any field lacks a description. `fix_borders.py` corrects a paragraph-border ordering issue in the Word output so the files pass schema validation.

After counsel review, the approved Word versions become the source of truth and the generator is retired for those documents.
